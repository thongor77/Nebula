# Dashboard Usability Log — Nebula

> Journal d'usage quotidien réel pour `themes/dashboard`, tenu par
> l'utilisateur sur 1 à 2 semaines une fois le thème installé comme
> thème de connexion réel (brief §10, `Nebula-Showcase-Dashboard-Theme-Brief.docx`).
> Ne pas déclarer le triptyque réussi ou non sur une première
> impression — voir le rapport de validation technique dans
> [`Dashboard-Theme-Report.md`](Dashboard-Theme-Report.md) pour ce qui a
> déjà été vérifié avant le début de cette période.

## Comment utiliser ce journal

Après installation (`sudo scripts/install-nebula.sh dashboard`), ajouter
une entrée datée à chaque observation notable — pas besoin d'une entrée
par jour, seulement quand quelque chose vaut la peine d'être noté par
rapport aux sept axes du brief ci-dessous.

## Axes à observer (brief §10)

- Ce qui reste agréable après un usage répété.
- Ce qui devient visuellement bruyant ou agaçant.
- Si les panneaux latéraux apportent une vraie valeur.
- Toute friction récurrente de focus/connexion.
- Toute bizarrerie multi-écran ou d'échelle.
- Si les contrôles sont placés là où la mémoire musculaire les attend.
- Si le triptyque se justifie encore face à une connexion centrée plus
  simple.
